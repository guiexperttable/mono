### SideIdent

Ƭ **SideIdent**: ``"west"`` \| ``"center"`` \| ``"east"``

The `SideIdent` type is utilized in various parts of the application to identify the position
of a component or an element on the horizontal axis within a layout. This can be seen in usage
within the `TableModel` and `AreaModelIf` classes to manage layout aspects such as column positioning
and adjustments.

The `SideIdent` is a string literal type that can have the following values:
- "west"  : Represents the left side on the horizontal axis of a layout.
- "center": Represents the center on the horizontal axis of a layout.
- "east"  : Represents the right side on the horizontal axis of a layout.

It is used as an argument in numerous functions and interfaces to specify which 'side' the operation pertains to.

Example:
- In the `TableModel` class, it's used in `getSideAreaWidth` and `getSideStartAndEndColumnIndex` methods to determine
  the position and the width of different sections.
- In the `ArgsAdjustColumnsToRowParentParams` and `ArgsRenderCellDiv` interfaces, it's used to provide classification
  of the area requested for operation.

These examples show how crucial this value is for the computation and organization of layout within the application.

**`See`**

 - ArgsAdjustColumnsToRowParentParams
 - ArgsRenderCellDiv
 - TableModel
 - AreaModelIf

[src/lib/table/data/side-ident.type.ts:31](https://github.com/guiexperttable/mono/blob/main/packages/table/src/lib/table/data/side-ident.type.ts#L31)

### ValueRowSortComparator

Ƭ **ValueRowSortComparator**: (`valueA`: `any`, `valueB`: `any`, `rowA?`: `any`, `rowB?`: `any`, `f?`: `number`) => `number`

#### Type declaration

▸ (`valueA`, `valueB`, `rowA?`, `rowB?`, `f?`): `number`

Represents a function that compares two values for sorting purposes.
The function takes two values of type T and optionally their corresponding row objects of type U,
compares them, and returns a number.
If the result is negative, it means 'valueA' comes before 'valueB' in the sorted order.
If the result is positive, it means 'valueB' comes before 'valueA' in the sorted order.
If the result is zero, it means the two values are considered equal for sorting purposes.

##### Parameters

| Name | Type | Description |
| :------ | :------ | :------ |
| `valueA` | `any` | The first value to be compared. |
| `valueB` | `any` | The second value to be compared. |
| `rowA?` | `any` | Optional. The row object containing valueA. |
| `rowB?` | `any` | Optional. The row object containing valueB. |
| `f?` | `number` | Optional. The direction. It is not necessary to use this value in the comparator, as this number is used as a factor (1 or -1) in the outer sort method. |

##### Returns

`number`

A number indicating the relative order of 'valueA' and 'valueB'.

### FocusType

Ƭ **FocusType**: ``"none"`` \| ``"cell"`` \| ``"row"``

The `FocusType` type alias provides an enumerated set of string literal values
which can be used to indicate the type of focus within the grid.

The values are:
- "none" : Indicating that cells and rows cannot have a focus.
- "cell" : Indicating that cells can have a focus.
- "row"  : Indicating that entire rows can have a focus.

Typically, this type is used within the `FocusModel` class,
specifically in the `constructor` and in the `setFocus` method,
to set `selectionType` property and determine where the focus is set respectively.

Here is a usage example with the `FocusModel` class:

```typescript
let focusModel = new FocusModel("cell");
focusModel.setFocus(2, 3);
```

In the above example, a `FocusModel` instance is created with a `FocusType` of "cell".
Then the focus is set to the cell at row index 2 and column index 3.

**`See`**

 - FocusModel
 - FocusModel#setFocus
 - FocusModelIf

### AggregatorName

Ƭ **AggregatorName**: ``"sum"`` \| ``"count"`` \| ``"avg"`` \| ``"min"`` \| ``"max"`` \| ``"countDistinct"`` \| ``"first"`` \| ``"last"``

The names of the built-in aggregators ([Aggregators](modules.md#aggregators)).

| name | result | uses |
|---|---|---|
| `sum` | sum, `0` for no numbers | numbers (`NaN` ignored) |
| `count` | number of rows | every row – the value does not matter |
| `avg` | sum / count of the numbers, `undefined` for none | numbers |
| `min`, `max` | smallest / largest value, `undefined` for none | numbers and valid `Date`s |
| `countDistinct` | number of different values | everything except `null`/`undefined`; dates by time |
| `first`, `last` | value of the first / last row | every row, the value as it is |

Text is never converted to a number (like Excel's SUM over a range): `"12"` does not count. Use an accessor such as
`row => Number(row.amount)` for numbers stored as text.

**`Example`**

```ts
const name: AggregatorName = "avg";
aggregate(orders, "total", name);
```

### Aggregators

• `Const` **Aggregators**: `Readonly`\<`Record`\<[`AggregatorName`](modules.md#aggregatorname), [`AggregatorIf`](interfaces/AggregatorIf.md)\>\>

The built-in aggregators by name ([AggregatorName](modules.md#aggregatorname)) – each one is an [AggregatorIf](interfaces/AggregatorIf.md), so `merge` combines
partial results correctly (the average of groups is the average of all rows).

- `sum` and `avg` sum with compensation (Neumaier): `0.1 + 0.2 + 0.3` is `0.6`, and splitting the data into groups
  does not change the result.
- Numeric aggregators use numbers only (`NaN`, text, `null` … are ignored); `min`/`max` also valid `Date`s;
  `count` counts rows; `countDistinct` ignores `null`/`undefined`; `first`/`last` take the value as it is.

**`Example`**

```ts
const { sum } = Aggregators;
let state = sum.init();
for (const order of orders) state = sum.add(state, order.total);
sum.result(state);                         // the same as aggregate(orders, "total", "sum")
```

### escapeHtml

▸ **escapeHtml**(`value`): `string`

Escapes a value for HTML text and for (double or single quoted) HTML attribute values:
`&`, `<`, `>`, `"` and `'` become entities; `null` and `undefined` become an empty string.

Use it whenever data (cell values, labels, ids from the server …) is written into `innerHTML` – otherwise a value
like `<img src=x onerror=alert(1)>` is executed as markup (HTML injection / XSS), and a `"` cuts an attribute value.

#### Parameters

| Name | Type | Description |
| :------ | :------ | :------ |
| `value` | `unknown` | any value; it is converted with `String(value)` |

#### Returns

`string`

the escaped text

**`Example`**

```ts
// in a cell renderer
const cellDiv = document.createElement('div');
const cellValue = 'Tom & Jerry <3';
cellDiv.innerHTML = `<div class="my-label" title="${escapeHtml(cellValue)}">${escapeHtml(cellValue)}</div>`;
```

**`Example`**

```ts
escapeHtml('<b>"Tom" & Jerry</b>'); // "&lt;b&gt;&quot;Tom&quot; &amp; Jerry&lt;/b&gt;"
```
